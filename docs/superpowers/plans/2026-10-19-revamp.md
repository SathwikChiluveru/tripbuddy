# TripBuddy Revamp Implementation Plan

**Goal:** Deliver a coherent travel UI and a tested, locally runnable backend.

**Architecture:** Preserve React, Express/Mongoose and existing URLs. Centralize frontend API access and backend session, validation and error boundaries. Use a dedicated local MongoDB database for development and an isolated database for integration tests.

**Spec:** PRODUCT.md; aesthetic and implementation choices delegated by user.

## Constraints and review focus

- Preserve discovery, registration/login, Google login when configured, trip CRUD/membership, profiles, uploads, and member chat.
- Never trust browser IDs for authorization. Test missing sessions and cross-user edits.
- Guard the last trip slot atomically. Test concurrent joins and duplicate joins.
- Bound JSON, uploads, lists and messages. Test invalid IDs, dates and payloads.
- Render usable loading, empty, failure and signed-out states; check desktop and mobile.
- Keep local demo data explicitly labeled and seed only a development database.

## Tasks

- [x] Backend regression tests: real HTTP requests against isolated MongoDB; verify failures against original backend before implementation.
- [x] Backend: app factory, persistent sessions, authenticated routes and sockets, validation, atomic membership, JSON errors, safe uploads and graceful startup/shutdown.
- [x] Frontend: shared API/session/navigation, complete landing/discovery/auth/trip/profile/chat screens and responsive design system.
- [x] Operations: environment examples, repeatable seed, real test command, isolated load test, useful README and Compose.
- [x] Verification: integration suite, concurrency test, frontend build/lint, browser journeys and visual review; launch local services.

## Ledger

- Baseline: backend test command is a sleep/echo placeholder; client dependencies absent; no environment files. Backend code inspection reveals unrestricted identity and room access, non-atomic joins, early registration response and broken string/subdocument membership handling.
- Ruling: execute in the supplied checkout with no commits or publishing; sandbox marks .git read-only. User asked to see the changed application here.
- Ruling: use native Node test runner and real MongoDB rather than add a test framework. Use a workspace npm cache and Node preserve-symlink flags to accommodate Windows sandbox path permissions.

- Ruling: replace Chakra with semantic React/CSS; network-blocked dependency installs required compatible cached React19/Vite6. Removed unused client packages and seven backend dependencies.
- Verification: real Mongo/HTTP/Socket.IO suite, bounded concurrent load, desktop/mobile browser journey, independent reviewer fixes, build/lint; details docs/verification.md.
- Review fixes: server-side personal/search pagination; per-trip queue normalized for mixed-case IDs; optional trusted proxy configuration.
